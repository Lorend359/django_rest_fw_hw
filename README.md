# Django REST Framework: Платформа онлайн-обучения

## О проекте

Это учебный проект, выполненный в рамках курса по Django REST Framework (DRF). В процессе разработки реализуется backend-часть платформы онлайн-обучения — RESTful API, предназначенный для SPA-клиента.

API предоставляет:

* управление курсами и уроками,
* регистрацию и аутентификацию пользователей (JWT),
* разграничение прав доступа по ролям,
* фильтрацию и сортировку данных,
* обработку платежей через Stripe,
* отображение профиля пользователя (с ограничениями),
* асинхронные уведомления и периодические задачи через Celery и Redis.

## Реализованные модули и домашние задания

### Домашняя работа 1: Вьюсеты и дженерики

* Настроен DRF и сериализаторы для моделей `Course`, `Lesson`, `CustomUser`, `Payment`.
* Реализованы CRUD-контроллеры для курсов и уроков через ViewSet и GenericAPIView.
* Подключена авторизация с помощью JWT.

### Домашняя работа 2: Права доступа

* Создана группа "Модераторы".
* Настроены права доступа:

  * Модераторы могут редактировать любые курсы и уроки,
  * но не могут создавать или удалять их.
* Создан кастомный permission `IsModerator` и настроены проверки в `get_permissions()`.

### Домашняя работа 3: Объектные права и владельцы

* Добавлены поля `owner` в модели `Course` и `Lesson`.
* Обычные пользователи могут создавать, редактировать и удалять **только свои** объекты.
* Настроены проверки через кастомный permission `IsOwner`.
* Создан метод `perform_create` для автоматической привязки владельца.

### Дополнительное задание: Ограничения на профиль пользователя

* Добавлены два сериализатора для пользователя: публичный и приватный.
* Настроено отображение полного профиля только владельцу.
* История платежей выводится только владельцу профиля.
* Добавлен permission `IsProfileOwner`.

### Домашняя работа 4: Валидаторы, пагинация и тесты

* Реализован кастомный валидатор для YouTube-ссылок в `Lesson`.
* Добавлена пагинация для списков уроков.
* Написаны тесты на создание, получение, обновление и удаление уроков.

### Домашняя работа 5: Документирование и безопасность

* Подключена автодокументация API через `drf_yasg` (Swagger / ReDoc).
* Интеграция с платежной системой Stripe: продукты, цены, сессии оплаты.

### Домашняя работа 6: Celery и фоновые задачи

* Настроен Celery и Redis для фоновых задач.
* Создана фоновая задача по отправке email-уведомлений при обновлении курса.
* Добавлено условие: письма отправляются только если курс не обновлялся в течение последних 4 часов.
* Настроен Celery Beat для ежедневной задачи:

  * Деактивация пользователей, не заходивших более месяца (`is_active = False`).

### Финальная работа: Docker и CI/CD

* Контейнеризированы все компоненты проекта (Django, PostgreSQL, Redis, Celery, Nginx).
* Настроен `docker-compose.yml` для запуска всех сервисов.
* Добавлены `Dockerfile`, `.env.example`, `nginx.conf`.
* Настроен CI/CD через GitHub Actions:
  * Установка зависимостей, линтинг и тесты,
  * Автоматический деплой на удалённый сервер по SSH при push в ветки `develope`, `feature/hw`, `feature/hw_2`.

## Как запустить с помощью Docker

1. Убедитесь, что установлен Docker и Docker Compose.
2. Создайте `.env` файл в корне проекта (если ещё нет) по шаблону `.env.example` и заполните нужные переменные.
3. Соберите и запустите проект командой:

```bash
docker-compose up --build
```

4. Проверка работоспособности сервисов:

* Backend (Django): http://localhost:8000/
* Swagger UI: http://localhost:8000/swagger/
* ReDoc: http://localhost:8000/redoc/
* PostgreSQL: порт 5432
* Redis: порт 6379

## Как запустить вручную без Docker

```bash
poetry install
poetry run python manage.py migrate
poetry run python manage.py runserver
```

Дополнительно:

```bash
poetry run celery -A config worker -l info -P eventlet
poetry run celery -A config beat -l info
```

## CI/CD и деплой на удалённый сервер

* При пуше в ветку `develope`, `feature/hw` или `feature/hw_2` запускается GitHub Actions workflow.
* Прогоняются тесты, устанавливаются зависимости и запускается сборка проекта в контейнере.
* При успехе выполняется деплой на сервер через SSH:
  * `git pull`
  * `docker-compose up -d --build`

Секреты (`SECRET_KEY`, `DATABASE_URL`, `STRIPE_KEYS`, `SSH_PRIVATE_KEY`) хранятся в GitHub Secrets.
